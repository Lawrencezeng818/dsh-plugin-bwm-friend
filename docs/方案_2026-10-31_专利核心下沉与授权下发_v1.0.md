## 零、先说结论：本轮复核推翻了 v0 方案的一半

### 0.1 我上一轮的技术判断错在哪

上一轮我提的方案是「host 负责取内核、client 负责用，因为 host 是 Node 进程可以读写文件」。**这条在技术上不成立**，原因三条硬约束：

| # | 硬约束 | 证据 |
|---|---|---|
| C-1 | `lib/client.js` 是**浏览器模块**（`window.__ModuleLoader__.load`），没有 `fs`，不能读本地文件 | `lib/client.js:1` |
| C-2 | client 在**模块顶层同步**解构内核：`const { createRuntime } = __bwmRequire('@laikaton/bwm-runtime-core')` | `lib/client.js:1743`、`2167`（`validMode/validPresence`） |
| C-3 | client 产物由 **DSH 框架按 `package.json` 的 `dsh.client` manifest 自动扫描伺服**，本项目无法拦截响应做动态合成 | `cordis.patch.yml` 头注 |

推论：**只要内核代码要进 client，就必须躺在 `lib/client.js` 里随包公开**。所以「把整份内核改成云端下发」在不动架构的前提下**做不到**——做了也只保护了 host 那一份，公开包里那份还在，等于零收益。

### 0.2 但结论方向仍然成立，只是实现路径要换

真正的问题不是「代码在不在云端」，而是：**专利实现（关系账本六步链、感知路由器）为什么必须跑在浏览器里？**

现状是：**计算在 client，持久化在 host**（`src/client.js:1148-1152` 注释原文：「账本走独立 store（settings 通道，宿主侧持久）」）。这是架构错位——持久状态由 host 拥有，而决定持久状态能否写入的准入裁决（专利4 的六步链）却在 client 内存里执行。按 `DOMAIN_POLICY`（Runtime State ≠ Persistent State）的既有裁决，这个边界本来就该收口。

**所以正确解法是：把专利核心下沉到 host，client 只留不含专利实现的薄协议面。**

收益是三重的：
1. **audit [F] 守卫自然变绿**——不含专利实现指纹，不再需要 `--expect-blocked`
2. **专利自我公开风险消除**——公开包里没有六步链与路由器实现
3. **架构纠正**——持久状态的准入裁决回到持有持久状态的一侧

## 一、三条路径对比

| 路径 | 做法 | 工作量 | 解决专利公开 | 解决订阅计费 | 判定 |
|---|---|---|---|---|---|
| **A｜runtime 全服务化** | 内核全移 host，client 纯协议客户端，presence/subscribe 走 HTTP | 大（client 状态机全改，延迟预算重做） | ✅ | ✅ | 过度，本阶段不取 |
| **B｜专利核心下沉（推荐）** | ledger/router 只在 host；client 保留 EventBus/Presence/协议面，ledger 改为远程 store | 中 | ✅ | ✅ | **取** |
| **C｜仅改 host 侧下发** | 只把 host 的 core 改成授权下载 | 小 | ❌（client 那份仍公开） | ⚠️ | 无效，不取 |

## 二、推荐路径 B 的机制

### 2.1 包拆分（闭源边界重划）

```
packages/
  bwm-runtime-core/        ← 公开面（Apache-2.0 或 UNLICENSED 均可）
    EventBus / Presence 状态机 / hello 握手 / validMode / validPresence / DOMAIN_POLICY
    ❌ 不含 relationship-ledger.js、perception-router.js
  bwm-cognitive-core/      ← 闭源专利面（UNLICENSED · private · 不进 npm 公开包）
    relationship-ledger.js（专利4 六步链）
    perception-router.js（专利5 感知路由）
```

`bwm-runtime-core` 的 `createRuntime(opts)` 从**内部创建账本**改为**必须注入账本实现**：

```js
// 现状 packages/bwm-runtime-core/src/index.js:653
const relationshipLedger = createRelationshipLedger(opts.relationshipLedger || {});

// 改后：不再 import ledger，改为必需注入；缺失即显式抛错，不做静默降级
if (!opts.ledger) throw new Error('BWM_RUNTIME_ERR: ledger provider required');
const relationshipLedger = opts.ledger;
```

### 2.2 两端各自注入

| 端 | 注入什么 | 位置 |
|---|---|---|
| **host**（`lib/index.js`） | 真账本：`require('@laikaton/bwm-cognitive-core').createRelationshipLedger()` | host 启动时 |
| **client**（`src/client.js:1152`） | 远程账本代理：`createRemoteLedgerStore()`——`append()` 走 `POST /bwm-friend/ledger/append`，host 算完返回 | 现有 `createLedgerStore()` 同位置替换 |

client 的 `createRuntime()`（`src/client.js:1115` 嵌入式握手处）不传 ledger，按新契约须显式传 `{ ledger: nullAllowed: true }` 或改用 `createRuntime({ ledger: remoteLedgerStub })`。**这是本方案唯一需要改 client 业务代码的地方，共 2 处。**

### 2.3 授权下发（B1-a 的落点，只作用于 host 侧）

`lib/index.js` 新增 `ensureCognitiveCore()`：

```
启动
 └→ 读 ~/.dsh-bwm-friend/license.json（token + exp + tier）
     └→ 命中且未过期 → 直接加载本地缓存（不联网）
         └→ 未命中 → POST {BWM_AUTH_BASE}/runtime/entitlement（复用现有 /auth/login/sms 会话）
             └→ 200 → GET /runtime/bundle?version=<pkg>（Bearer token，**完全鉴权，无公开地址**）
                 └→ 解密（密钥由 token 经 HKDF 派生）→ 落盘 ~/.dsh-bwm-friend/runtime/<ver>/cognitive.js
                     └→ 到期但缓存仍有效 → 7 天宽限，宽限内静默续期
                         └→ 宽限耗尽 → 降级：host 无账本能力（基础功能照常，跨端同步与账本失效）
```

关键设计：**密钥由 token 派生，不硬编码**。token 无效 → 派不出密钥 → 解不开包。

### 2.4 为什么这样 [F] 守卫会变绿

`scripts/audit-release.mjs` 的 [F] 是按**专利实现代码指纹**拦截的（retained 快照 / generation 代次回落 / 被拒事件不入历史 / 专利5 路由器 / 专利4 关系账本）。这些指纹全部来自 `relationship-ledger.js` 与 `perception-router.js`。两者不随包 → **F=0，c=0，a+b=0 → 真绿**，`--expect-blocked` 可退役。

## 五、风险（不粉饰）

1. **账本写入变异步 = 时序风险**：现在 client 内存里同步算完六步链就落 store；改为远程后，append 有往返。若业务有「写完立刻读」的路径，会出现读到旧值。**必须先盘点所有依赖账本同步性的调用点**，这是本方案最大技术风险。
2. **`perception-router` 的归属未定**：它是否被 client 的 presence 状态机直接调用，我尚未验证完（`core/index.js:15` 引入，具体调用点待查）。若 presence 依赖它，则路由器不能下沉，需再拆一层（公开的路由骨架 + 闭源的裁决表）。**这是待确认项，写方案时不得假设。**
3. **契约破坏波及测试面**：`createRuntime` 从可选 ledger 变必需注入，属 breaking change，需 minor 版本 + CHANGELOG 显式标注。
4. **Hub 单点**：B1-a 完全鉴权下载，Hub 挂则新用户拿不到认知核心。缓解：老用户靠本地缓存 + 7 天宽限；新用户降级可用。**这是 B1-a 的已知代价，创世者已确认接受。**
